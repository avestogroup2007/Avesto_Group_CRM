# Правила работы над Avesto Group CRM

Файл читается ассистентом автоматически в начале каждой сессии. Здесь только
то, что нельзя вывести из кода и что уже стоило ошибок.

## Стек

- **Бэкенд**: Node 20+, Express, Prisma, PostgreSQL. ESM (`"type": "module"`).
- **Фронтенд**: React 18, Vite 6, Tailwind 4. Без TypeScript.
- **Интеграция**: iikoServer API (`/resto/api`), XML и OLAP.
- Комментарии и интерфейс — на русском. Код пишется в стиле окружающего файла.

## Перед коммитом

1. `npm run lint` в `backend/` и `frontend/` — должно быть чисто.
2. `npm run build` во `frontend/`.
3. Правки проверяются **на реальных данных**, а не только на отсутствии ошибок
   линта: в этом проекте несколько багов выглядели как «работает», потому что
   ошибку глушил `.catch(() => [])`.

Коммитить **прямо в `main`** — так работает владелец. Отдельные ветки не
создавать, если не попросили.

## Чего не делать

- **Не запускать `npm test` на рабочей базе.** Тесты создают ~20 учёток
  (`cash_test_director`, `acc_sysadmin`, `tasks_outsider` и т.п.) и засоряют
  списки сотрудников. Нужна отдельная тестовая база.
- **Не ориентироваться на `npm run format:check` под Windows.** Он падает на
  ~105 файлах из-за CRLF (`core.autocrlf=true`, в Prettier дефолт `endOfLine:
  "lf"`). Проверять так: `npx prettier --check --end-of-line auto .`
- **Не глушить ошибки интеграции через `.catch(() => [])`** без явного
  комментария, зачем. Именно так раздел «Активность персонала» год показывал
  пустоту: сервер отвечал `400 Unknown OLAP field`, а ошибка молча терялась.
- **Не класть секреты в репозиторий.** `backend/.env` в `.gitignore`; ключи
  iiko, Telegram и Anthropic задаются только в окружении хостинга (Render).

## Особенности iiko на этой установке

Проверено на `avesto-uz-co.iiko.it` в октябре 2026.

| Что нужно | Путь | Параметры |
|---|---|---|
| Продажи, P&L, себестоимость | `/resto/api/v2/reports/olap` | `reportType` SALES / TRANSACTIONS / DELIVERIES |
| Сотрудники | `/resto/api/employees` | — |
| Должности (коды → названия) | `/resto/api/employees/roles` | — |
| **Отработанное время, явки** | `/resto/api/employees/attendance` | **`from`/`to`** (не `dateFrom`) |
| Кассовые смены | `/resto/api/v2/cashshifts/list` | `openDateFrom`/`openDateTo`/`status` |
| Подразделения | `/resto/api/corporation/departments` | — |

**Недоступно:** всё семейство `/resto/api/v2/documents/export/*` отвечает 404 —
API документов на этой установке не включён. Отчёт производства и акт
приготовления работать не могут, это не чинится кодом.

**Важные детали:**

- Сессия у iikoServer **одна на пользователя**. Параллельные запросы её рвут —
  обращения идут строго последовательно (см. `acquireKey`/`releaseKey`).
- Поля OLAP нужно писать точно: `OrderWaiter` не существует, правильное —
  `OrderWaiter.Name`. Неверное имя даёт `400 Unknown OLAP field`.
- Названия подразделений — дословно с префиксом: `AC Микрорайон`,
  `AS Наврузий цех`, `ICG Кейтеринг`. Любое расхождение в `branch.iikoDept` —
  и фильтр по филиалу молча возвращает пустоту, а «все филиалы» работают.
- В карточке сотрудника приходит **код** должности, название — только из
  справочника ролей.
- Типы оплат в iiko свои у каждой сети. Карта соответствий —
  `services/cashReconcile.js`, при появлении нового типа правится там.

## Данные и производительность

- Отчёты iiko кэшируются через `services/iikoCache.js`: память + БД. Отчёт за
  **закрытый** период неизменен и хранится бессрочно; период с «сегодня» живёт
  3 минуты и отдаётся устаревшим, пока обновляется в фоне.
  Холодный отчёт за месяц — ~17 секунд, из кэша — ~130 мс.
- Ночной прогрев: `POST /api/iiko-cron/warm` с секретом в `X-Cron-Secret`.
  Греть надо периоды **в том виде, как их шлёт интерфейс** (пресеты
  заканчиваются сегодняшним днём, а не вчерашним) — иначе ключи не совпадут.
- Списки людей фильтруются через `util/people.js`. По флагу `active` **не
  фильтровать**: это право входа, а не факт трудоустройства — синхронизация
  намеренно заводит линейный персонал неактивным.

## Локальная разработка

PostgreSQL 18 поднят отдельным кластером на порту **5434** (пароль системного
`postgres` неизвестен): `C:\Users\user\pgdata-avesto`, пользователь `crmadmin`,
база `procystem`. После перезагрузки запускать вручную:

```
"C:\Program Files\PostgreSQL\18\bin\pg_ctl" -D C:/Users/user/pgdata-avesto -l C:/Users/user/pgdata-avesto/server.log -o "-p 5434" start
```

Демо-вход после `npm run seed`: `sysadmin` / `changeme123`.
